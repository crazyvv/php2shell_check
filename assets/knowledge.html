PHP2Shell 漏洞知识库

本页把社区研究中的内存破坏、跨请求状态和会话上传进度链路，整理成适合开发、安全和运维共同复核的知识。利用链按前置条件、数据流、观测点和处置说明，不提供可执行载荷。

证据边界

社区研究的复现结论、在野情报和补丁分析需要分别核验。版本响应头、会话 Cookie、HTTP 500/502、响应时间或错误文本都不能单独确认漏洞、利用成功或修复完成。

请求在什么阶段进入风险路径

1. Web / SAPI 收到请求mod_php、FPM、CGI 等运行模型不同
→
2. multipart / rfc1867 解析可能早于业务 PHP 代码和部分请求初始化
→
3. 会话上传进度更新按配置写入会话状态，字段名可以修改
→
4. 业务代码与请求关闭读取会话、反序列化、析构并清理全局状态

研究的共同重点是：解析或错误处理被中断时，当前请求或复用 worker 中的状态是否仍被后续阶段使用。补丁因此不仅涉及会话功能，也涉及 OOM 处理、早期全局重置和 multipart 期间的对象行为。

五类利用链：前置条件、传播路径与防守点

A

会话写入 + 应用 LFI

前置：上传进度路径可写入会话，应用另有本地文件包含缺陷。

传播：上传元数据进入会话存储，应用随后包含相应会话文件。

防守：修复 LFI，隔离会话存储，禁止会话目录被 Web/PHP include。关闭上传进度只能减少这条路径。

B

反序列化清理重入

前置：攻击者能控制进入反序列化器的数据，并存在可触发的对象生命周期行为。

传播：失败或清理阶段发生析构重入，已释放的内部条目再次被访问。

防守：避免不可信反序列化，更新 PHP，审计对象析构与调用点；用 ASAN/崩溃栈复核，不能以普通 500 归因。

C

会话序列化处理器不一致

前置：同一会话在不同路径或请求中使用不同 serialize_handler，并具备对象链条件。

传播：一种格式写入的数据被另一种格式解释，失败清理仍可能触发对象生命周期。

防守：统一全部池、目录和虚拟主机配置；核对实际 Web SAPI，不能用 CLI 配置替代 Web 配置。

D

mod_php 解析期 OOM 与陈旧执行状态

前置：易受影响的 PHP 构建与 mod_php 生命周期，multipart 解析进入内存失败路径。

传播：解析被非局部跳转中断，关闭阶段继续读取不完整的执行器全局状态。

防守：安装完整补丁并重启全部 worker；关联 Apache/PHP 崩溃和请求日志。自查台不会主动制造 OOM。

E

FPM 跨请求陈旧反序列化状态

前置：同一 FPM worker 被复用，前一请求在会话解码期间异常中止，后一请求较早进入上传解析。

传播：后一请求在正常初始化前接触前一请求残留的反序列化状态。

防守：更新并重启 FPM 池；关联 worker PID、两次请求和错误日志。单次响应无法证明命中同一 worker。

链名称和根因模型来自下方 ikow 技术分析。页面省略载荷布局、内存地址推导、命令执行及故障注入步骤。

补丁覆盖什么，仍要核对什么

层面补丁或控制目的复核要点
OOM 处理避免内存失败后继续使用不完整的执行状态确认实际实例达到官方基线、包修订已安装、全部 worker 已重启
早期全局重置在 multipart 处理前清理序列化相关状态逐个核对 FPM 池、容器和后端，避免仍有旧 worker
rfc1867 对象约束限制上传进度解析期间实例化对象和触发魔术方法不等于应用 LFI、任意反序列化等独立缺陷已修复
会话加固修正会话 ID 来源与处理器生命周期等问题社区文档指出部分改动来自独立 PR；发行版是否完整回补须看厂商公告
配置缓解关闭 upload_progress、统一 handler、限制 multipart只覆盖部分路径，不能替代官方补丁；关闭进度不证明 OOM 路径已修复
应用层修复 LFI、危险反序列化和不安全上传引擎补丁不自动修复应用缺陷；会话/上传目录要与可执行和可包含路径隔离

本项目使用已核对的上游基线：8.2.35、8.3.36、8.4.27、8.5.12。达到基线仍显示“待核验”，因为响应声明、发行版回补和实际运行进程不是同一份证据。

扫描证据如何升级

低可信线索版本/产品响应头、页面路径、上传表单、Cookie 名称、错误文本
配置与实例材料实际 Web SAPI、PHP 版本、INI、软件包修订、运行映像和 worker PID
补丁证据官方/厂商公告、安装包来源、运行映像一致、更新后的进程已重启
事件复核同一实例的访问日志、崩溃栈、进程与文件/网络遥测的时间关联

可选“上传进度基础观察”只发送一次普通文本文件，不指定会话 ID、不回读文件。出现 PHPSESSID 也只记录为线索；没有 Cookie 也不能证明功能关闭。

在野情报与 IOC 的使用方式

EXPLOITATION.md 汇总时间线、公开研究、攻击模式、恶意软件活动、网络基础设施、文件哈希和请求特征。这些内容变化快，不能作为永久黑名单。应保留来源和观测时间，在 SIEM 中把异常 multipart、PHP/worker 错误、子进程、会话文件和出站连接关联起来；单个 IP、User-Agent 或默认字段名都可能被复用或修改。

本项目的处理

不把社区 IOC 内置为漏洞判定，也不自动拦截。管理员可将已验证的规则部署到现有 WAF/IDS/SIEM；上线前应做语法校验、TLS 可见性检查、请求体截断测试和合法上传误报基线。
