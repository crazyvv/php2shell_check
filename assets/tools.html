Bash 主机巡检

同一脚本分发到多台主机。直接运行即可检查 Java、NGINX 和 Apache，无需预先知道主机运行了哪些服务。

下载 x2shell-check.sh

随当前服务版本提供 · 单文件 · 无需 Python

在目标主机运行

下载后将文件放到目标主机，在文件所在目录执行。

bash x2shell-check.sh

结果输出到终端。默认不联网，JVM 诊断附加默认关闭。

检查覆盖批量执行结果判读生产运行专项参数

检查覆盖

Linux 能提供进程和文件映射证据。macOS 可盘点可见的 Java 安装和启动器线索，NGINX 与 Apache 主机专项会标记为不可采集。

Java / JVM

核对运行中的 JVM、磁盘 JDK、构建号、CPU 特性与缓解参数线索。生效参数可选诊断附加。

NGINX

核对运行映像、版本、五项 CVE 的上游范围，以及二进制模块、磁盘配置与 SCTP 线索。可关联同一挂载命名空间内进程的绝对配置入口，限量展开常见 include 并标出证据文件与行号。

Apache HTTP Server

核对 httpd、mod_http2、独立模块版本，并区分虚拟主机块内外的 HTTP/2 配置线索。

批量执行与留档

在每台主机各执行一次。回收时将主机标识、执行时间、报告文件和退出码一并留档。

status=0
bash x2shell-check.sh --all --json > host-audit.json || status=$?
printf 'exit_code=%s\n' "$status"

批量平台直接执行扫描命令即可收到脚本退出码。上方示例会保留报告并打印退出码，便于人工查看。

批量 JSON 的 exit_codes 记录各专项的返回值。报告包含主机路径和进程线索，适合在内部巡检流程中留存。

结果判读

0
扫描范围内未命中风险门禁。仍应查看各专项的观察范围。
1
至少一项命中风险门禁。复核对应组件的版本、运行实例与厂商回补。
2
出现参数或采集错误。查看错误输出并检查报告是否完整。
3
证据不足或覆盖不完整。检查权限、容器视图或平台支持。

Java、NGINX 和 Apache 在自动盘点进程时，若检测到容器或受限的 /proc 挂载，会将 coverage.process_visibility_limited 标为 true。NGINX 和 Apache 也会标记仍存在但无法读取进程名称的 PID。已有风险命中仍返回 1，其余情况返回 3。需要核验整台主机时，应在能够看到宿主机进程的环境运行脚本。

同时出现多个状态时，批量模式优先返回 2，其次 1，再其次 3。请结合各专项退出码阅读报告。

生产运行与资源上限

常规批量巡检使用 bash x2shell-check.sh --all --json，并由批量平台限制并发及单主机任务时长。Linux 每个专项最多检查 2,048 个 PID，NGINX 和 Apache 各最多深入检查 24 个匹配进程。macOS 的 Java 进程清点最多处理 2,048 条进程记录。

Java 的显式 --root 总计最多遍历 10,000 个条目，--apps 另有 10,000 个条目额度。两者都限制在起始文件系统内，并遵守各自的搜索深度。达到条目上限且后面还有数据时，报告会标记覆盖不足。没有命中风险门禁时返回 3，已有命中仍返回 1。条目上限约束读取量，单次文件系统访问仍取决于目标主机的 I/O 响应。

  • --jcmd 会主动附加到 JVM，可能启动诊断监听器或造成短暂停顿。延迟敏感业务保持默认设置。
  • --java-path 会以当前账号执行指定的 Java 启动器。仅在需要版本复核时指定可信文件。需要 timeout 或 gtimeout。两者都缺失时，脚本报错退出。
  • --cpuinfo 只接受可读的普通文件，默认最多读取并解析 1 MiB 的 CPU 信息。命名管道和设备文件会被拒绝。
展开自定义扫描上限

打开 x2shell-check.sh，在开头的「资源上限」区修改对应变量的数值。按正整数填写，保留等号两边的写法。修改后直接用原命令执行，建议先在单台主机验证覆盖和运行时间，再分发同一份脚本。

进程和目录
PROCESS_SCAN_LIMIT=2048、WEB_PROCESS_MATCH_LIMIT=24 和 DIRECTORY_ENTRY_LIMIT=10000。ROOT_DEPTH=8 和 APPS_DEPTH=3 是默认深度，可分别由 --root-depth 和 --apps-depth 覆盖。
Web 文件读取
WEB_CONFIG_FILE_LIMIT=64、WEB_CONFIG_BYTE_LIMIT=65536、NGINX_INCLUDE_DEPTH_LIMIT=8、WEB_BINARY_BYTE_LIMIT=16777216 和 APACHE_MAPS_BYTE_LIMIT=1048576。离线 CPU 信息另由 CPUINFO_BYTE_LIMIT=1048576 限制。带 BYTE 的值以字节计。
单次命令超时
PACKAGE_QUERY_TIMEOUT=2、JCMD_TIMEOUT=3 和 JAVA_VERSION_TIMEOUT=30，单位为秒。软件包查询收到超时终止信号后还有 1 秒退出时间，随后会被强制终止。主机需要有 timeout 工具。Java 版本查询也支持 gtimeout。

专项参数

常规巡检无需追加参数。需要缩小范围或补取证据时再选择以下命令。

只检查一个组件 
bash x2shell-check.sh --java4shell --json
bash x2shell-check.sh --nginx2root --json
bash x2shell-check.sh --apache2root --json
补查嵌入式 JDK 或非标准 Web 服务路径 
bash x2shell-check.sh --java4shell --root /opt/my-service
bash x2shell-check.sh --nginx2root --nginx-path /opt/nginx/sbin/nginx --nginx-config /opt/nginx/conf/nginx.conf
bash x2shell-check.sh --apache2root --apache-path /opt/httpd/bin/httpd --apache-config /opt/httpd/conf/httpd.conf

将示例路径换成目标主机上的实际路径。达到递归深度上限时，Java 报告会记录覆盖缺口。

读取运行中 JVM 的生效参数 
bash x2shell-check.sh --all --jcmd

诊断附加需要已有 jcmd，仅尝试同用户 JVM，可能启动诊断监听器或短暂停顿 JVM。

核验 PHP 或导入扫描页

Bash 报告供批量巡检留档。核验 PHP 或需要在网页关联业务 URL 时，使用 Rust collect 生成可导入的主机报告。
